# QQ 跳一跳助手

适配当前荣耀 400（DNN-AN00，Android 16，1264×2736）上的 QQ 跳一跳画面。通过 USB / ADB 截图识别棋子与平台，发送按压，实现连续跳跃。优先落在平台内，目标瞄准中心，不能保证永不掉落或每次中心加分。

## 使用

1. USB 连接手机并解锁，开启 USB 调试；仅充电时同时开启“仅充电模式下允许 ADB 调试”。允许本电脑授权。
2. 自己在 QQ 打开跳一跳，进入可起跳画面。
3. 双击本目录的 **启动.bat**。
4. 点击 **检查画面**，核对绿色标记在棋子脚底、红色标记在下一平台顶面中心。
5. 初次使用点击 **校准试跳（3次）**。确认落点正常，再点 **开始**。参数自动保存在 `settings.json`。
6. **暂停**按钮停止后续跳跃。窗口获得焦点时也可按 **Esc**。已经发送到手机的按压可能完成；关闭窗口同样停止后续操作。

校准会实际跳跃。运行中保持手机解锁和游戏前台，不要手动按压游戏。运行开始时读取窗口参数，修改后需暂停再开始。等待时间默认 0.5 秒，是画面落稳后的额外等待；截图、前台检查和输入会增加每跳总耗时。特殊平台不主动延长等待，但调试或处理耗时仍可能触发停留奖励。

窗口预览裁剪了手机画面的上下空白，以便看清棋子和瞄准点；它是每跳前的识别结果，不是实时投屏。

## 自动暂停

- 未连接、未授权或连接多台设备。
- QQ 不在前台、锁屏、画面持续变化。
- 棋子、目标平台或落地状态识别不可靠。
- 等待期间画面改变，或落点明显偏离目标。
- 游戏结束通常会因无法识别有效游戏画面而暂停；不点击重开按钮。

暂停后按提示处理，再点“检查画面”或“开始”。部分异形、低对比度、遮挡平台可能需要人工处理；识别失败时不会盲跳。游戏结束由用户手动重新开局。

## 参数与文件

- 按压系数：以统一 720 像素宽度计算的距离乘以系数，单位 ms/归一化像素，初始 2.0。成功跟踪落点后小幅自动修正。
- `jumpbot.py`：识别、ADB、控制循环和窗口。
- `settings.json`：本机校准参数。
- `jumpbot.log`：状态和错误日志。
- `diagnostics/before.png`、`after.png`：最近一次试跳前后的画面，用于定位识别问题。
- `tools/platform-tools`：Google 官方 ADB；无需模拟器或额外投屏软件。
- `.venv`：独立 Python 环境。

当前环境已配置。重建环境时运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

ADB 可从 https://developer.android.com/tools/releases/platform-tools 下载，将 `platform-tools` 解压到 `tools` 下。

离线检查（不操作手机）：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

开发用真机验证：`validate_live.py` 默认只检查画面；显式传 `--jumps N` 才执行至多 N 跳。不要和窗口同时运行。

自动化操作可能受 QQ 或小游戏规则限制，切换平台不能保证账号安全。
